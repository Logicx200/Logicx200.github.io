# 整体使用说明

## 这套东西是什么

一个**本地优先**的摄影归档网站。打开就是首页：随机一张照片变成可交互的三维点云，
旁边写着这张的拍摄参数；导入照片有两种方式，结果完全一样：

**方式一（推荐，最直观）：把文件夹拖进网页**

```powershell
npm run serve        # 打开 http://127.0.0.1:4173
```

然后切到顶部的 **「导入」** 标签，把你的照片文件夹**整个拖进去**：

* 浏览器当场读取 EXIF 拍摄参数、解析"几月几日何处拍摄"式文件夹名、用 Canvas 生成缩略图；
* 全程在本机完成，**照片不会被上传到任何地方**；
* 处理完会列出一张结果表：日期、地点、相机、参数，识别不对的可以**当场改**（改动会存成
  `overrides`，下次导入自动沿用）；
* 点「写入站点目录…」，在弹出的选择框里选 **本项目里的 `public` 目录**
  （也就是 `photo-journal\public`，里面有 `index.html` 的那个）。
  导入器会先校验这个目录确实是本站目录，**选错会直接报错并告诉你该选哪个，绝不会在你别的文件夹里乱建目录**；
* 写入完成后页面会**自动切回相册**，新导入的照片带绿色"刚刚导入"角标，顶部统计、时间轴、地图、统计页同步更新。

> 写入过一次后浏览器会记住这个目录，以后点一下就行；换电脑或清空浏览器数据后需要重新选一次。
> 如果浏览器不支持写目录（Safari/Firefox），会自动改成「下载 zip」，解压后覆盖仓库里的 `public/` 即可。

**方式二：命令行**

```powershell
npm run import -- --src "D:\照片归档"        # 生成索引 + 缩略图
npm run import -- --src "D:\照片归档" --copy  # 连原图一起进仓库
```

两种方式产出的文件格式一致，可以混用。整个站点是纯静态文件，不需要数据库、不需要常驻服务器，
可以放 GitHub Pages、Cloudflare Pages、对象存储，甚至 U 盘。

```
你的照片文件夹（命名很乱也没关系）
        │
        │  拖进网页 / npm run import
        ▼
public/data/*.json  +  public/media/{thumbs,previews}
        │
        │  npm run serve（本地看） · npm run build（发布）
        ▼
首页点云 + 时间轴 / 地图 / 参数筛选 / 统计 / 重复检测 / 待确认
```

## 1. 环境准备

只需要 Node 20 以上（推荐 22/24）。

```powershell
node -v          # 需要 >= 20
cd photo-journal
npm install      # 装 exifr（读 EXIF）与 sharp（生成缩略图，可选但强烈建议）
```

> 如果你所在网络访问 npm 较慢，可以先设置镜像：
> `npm config set registry https://registry.npmmirror.com`

## 3. 导入你自己的照片

### 3.1 拖进网页（最直观）

```powershell
npm run serve
```

打开页面 → 点顶部 **「导入」** → 把文件夹拖到虚线框里（也可以点「选择文件夹」）。
支持的浏览器：Chrome / Edge / 其他 Chromium 内核浏览器（拖文件夹、写目录）。
Safari / Firefox 也能用，只是"写入站点目录"会退化成"下载 zip"。

导入页上还有两个选项：

* **轻量**（默认）：只保存缩略图 + 1600px 预览图，约 0.3 MB/张，适合放 GitHub；
* **完整**：连原图一起写进 `media/originals/`，照片库会很大，超过 2GB 不建议提交到 GitHub。

处理过程中可以直接看到每张照片的识别结果，表格里点「修正」能改日期/地点/标签；
改过的内容会保存成 `public/data/archives.json`，命令行下次导入会自动套用。

**关于"会不会把已有的照片冲掉"**：不会。写入时会把本次导入的照片与站点上已有的照片
**按 id 合并**（同一张照片重新导入算"更新"），页面上会先告诉你"新增几、更新几、保留原有几、合计几张"。
想彻底重来就勾掉数据目录重新导入，或命令行加 `--clean`。

### 3.2 命令行

```powershell
npm run import -- --src "D:\照片归档"

# 连原图一起复制进 public/media/originals（仓库会变大，见存储方案）
npm run import -- --src "D:\照片归档" --copy

# 先看看它怎么理解你的文件夹名，不写任何文件
npm run import -- --src "D:\照片归档" --dry-run
```

常用参数：

| 参数 | 说明 |
| --- | --- |
| `--src <目录>` | 照片根目录（递归扫描） |
| `--copy` | 把原图复制进 `public/media/originals/` |
| `--origin-base <URL>` | 原图托管在对象存储/CDN 时的前缀，灯箱即可下载原图（见 `docs/存储方案.md` 方案 B） |
| `--no-previews` | 不生成 WebP 缩略图（仓库最省空间，但浏览慢） |
| `--force` | 重建已存在的缩略图 |
| `--clean` | 先清空 `public/data` 与 `public/media` 再导入（彻底重来） |
| `--duplicates` | 额外打印检测到的重复照片分组 |
| `--dry-run` | 只打印识别结果 |
| `--limit 50` | 只处理前 50 张（调试） |
| `--concurrency 8` | 并发数（机械硬盘建议 2~4） |
| `--include-video` | 顺带索引 mp4/mov |

也可以把参数写进 `photojournal.config.json`（复制 `photojournal.config.example.json` 改名即可），
之后直接 `npm run import`。

## 4. 本地预览 / 部署

```powershell
npm run serve                 # http://127.0.0.1:4173
npm run build                 # 产出 dist/（含 .nojekyll）
```

部署到 GitHub Pages 有两条路：

* **A. 简单**：直接提交 `public/`，仓库 Settings → Pages → Source 选 `main` 分支的 `/public` 目录。
* **B. 标准**：用仓库里已经写好的 `.github/workflows/deploy.yml`，
  它会跑 `npm run build` 并把 `dist/` 发布到 Pages（Settings → Pages → Source 选 **GitHub Actions**）。

两种方式都要求已经提交了 `public/data` 与 `public/media`（它们就是站点内容本身）。

首次推送：

```powershell
git init
git add .
git commit -m "摄影记录站点：首次导入"
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

> 站点默认标题是"我的摄影记录"，改 `photojournal.config.json` 里的 `title` / `subtitle` 后重新导入即可。

## 5. 它到底能从照片里读到什么

### 5.1 相机拍摄参数（EXIF / XMP）

| 字段 | 来源标签 | 说明 |
| --- | --- | --- |
| 拍摄时间 | `DateTimeOriginal` | EXIF 里最权威的拍摄时刻 |
| 备用时间 | `CreateDate` / `DateTimeDigitized` | 有些导出图只有这个 |
| 相机 | `Make` + `Model` | 自动去掉重复的品牌前缀 |
| 镜头 | `LensModel` / `Lens` / `LensInfo` | |
| 光圈 | `FNumber`（无则用 `ApertureValue` 换算） | 显示成 `f/2.8` |
| 快门 | `ExposureTime`（无则用 `ShutterSpeedValue`） | 显示成 `1/250` 或 `8s` |
| 感光度 | `ISO` / `ISOSpeedRatings` | |
| 焦距 | `FocalLength` + `FocalLengthIn35mmFormat` | 显示成 `35mm (52mm eq.)` |
| 曝光补偿 | `ExposureCompensation` | |
| 曝光模式 | `ExposureProgram` | 手动 / 光圈优先 / 快门优先… |
| 测光 / 闪光 / 白平衡 | `MeteringMode` / `Flash` / `WhiteBalance` | |
| GPS | `GPSLatitude` / `GPSLongitude` / `GPSAltitude` | 转成十进制度数 |
| 星级 / 色标 / 关键词 | `Rating` / `Label` / `Keywords`（XMP、IPTC） | Lightroom 的评级会带出来 |
| 后期软件 | `Software` / `CreatorTool` | 判断是否 Lightroom / Photoshop / Capture One 导出 |
| 版权 / 作者 / 描述 | `Copyright` / `Artist` / `ImageDescription` | 有就显示在详情里 |

拍摄时间刻意**保留相机本地时间**（不做 UTC 换算），否则跨时区旅行拍的照片会整体偏移几小时。

### 5.2 Lightroom 导出的照片能不能读参数？

**能，而且和相机直出图一样完整。** 关键点：

* Lightroom 导出 JPEG/TIFF 时**默认保留 EXIF**，"元数据"里如果选了"全部"就什么都不会丢。
  导出对话框里如果选了"移除位置信息"或"仅版权"，那 GPS / 部分字段才会没有。
* 用"导出为 DNG"或"在 Lightroom 里编辑原图"时，参数同样在文件里。
* 能额外读到的是 XMP 里的 **星级、色标、关键词**（`Rating` / `Label` / `Keywords`），
  站点会拿来做筛选。
* **读不到的是"调整参数"**：曝光度、色温、曲线、蒙版、局部调整这些只存在于
  Lightroom 目录（`.lrcat`）或同名 `.xmp` 附属文件里，导出的 JPEG 里没有。
  站点能判断的只是"这张是被 Lightroom 处理过的"（通过 `Software` 字段）。

> **虚拟副本 / 堆叠 / 收藏夹** 这些 Lightroom 内部组织信息也在目录里，
> 不会跟着导出文件走。如果你希望按 Lightroom 的评级/收藏夹浏览，
> 建议在 Lightroom 里先"导出为文件夹结构"，再让本工具导入。

### 5.3 手机照片

iPhone/安卓照片同样带 EXIF 与 GPS，没问题。HEIC 也能读，
但 sharp 对 HEIC 的支持取决于系统解码器，失败时会自动回退（见下）。

### 5.4 RAW（.dng/.cr2/.nef/.arw…）

索引和 EXIF 都能读；**缩略图可能生成不了**（依赖 libvips 是否带 RAW 解码）。
遇到读不了的情况：
* 站点会退回到"直接使用原图"（能看，只是加载慢）；
* 或者先在 Lightroom 里导出成 JPEG 再入库——这也更符合"归档成品"的思路。

## 6. 文件夹名自动识别（详见 `docs/文件夹名解析说明.md`）

支持这些写法（可以混搭）：

```
2024年/10月3日 杭州西湖/DSC01234.JPG
2024年/10月4日 西溪湿地 晨雾/
2024-12-31 上海外滩 跨年/IMG_20241231_231805.jpg
2023/10/1日 国庆 北京/
2022年/国庆/                       ← 只有节日，年份取父目录
2022年/扫街/10-06 成都宽窄巷子/      ← 年份取父目录
2023/精选 原片 归档/                ← 没有地点，退化为"未识别"
未整理/手机照片/IMG_20210405_090001.jpg  ← 日期从文件名取
```

识别顺序：**文件名/文件夹里的完整日期 → 父目录年份 + 月日 → 节日 → EXIF → 文件修改时间**。
每个结果都带"来源"和"置信度"，识别不出来的会在**「待确认」**标签页列出来，
你可以在 `photojournal.config.json` 的 `overrides` 里手动纠正后重新导入：

```json
{
  "overrides": {
    "2023/精选 原片 归档": { "date": "2023-08-12", "location": "杭州", "tags": ["夜景"] },
    "/扫街\\/.*2022/":      { "location": "杭州 湖滨" }
  }
}
```

键可以用路径片段（包含即命中），也可以写成 `/正则/`。

## 7. 站点功能

| 视图 | 内容 |
| --- | --- |
| **首页** | 随机挑一张照片变成**三维点云**，鼠标拖动旋转、滚轮缩放，旁边列出这张的拍摄参数（详见第 7.4 节） |
| **导入** | 把照片文件夹拖进网页，当场读 EXIF、识别文件夹名、生成缩略图，可逐张人工修正，然后写回仓库目录或导出 zip |
| **相册** | 等高行式瀑布流，悬停显示日期与地点，支持大图/紧凑两档；点击进灯箱 |
| **时间轴** | 年 → 月 → 缩略图，点击月份直接筛出该月 |
| **地图** | 内嵌 Natural Earth 海岸线（离线，不请求任何地图服务），GPS 光点聚合、缩放平移、点击按地点筛选 |
| **统计** | 照片数/地点数/跨度、逐月柱状图、相机/镜头/光圈/焦距/ISO/地点排行、日期来源质量 |
| **重复** | 感知哈希找出内容相同/几乎一样的照片（重复导出、改尺寸、修图前后、连拍），给出建议保留项与可省空间 |
| **待确认** | 日期或地点没识别出来的照片列表，方便人工补 |
| 侧栏筛选 | 年份、月份、地点、相机、镜头、标签、星级、日期来源、是否有 GPS，可组合 |
| 搜索 | 地点、说明、相机、镜头、光圈…全字段模糊搜索（按空格分词） |
| 灯箱 | 大图 + 完整参数 + 下载原图 + 在地图上查看；`←/→` 切换、`Esc` 关闭、`I` 隐藏信息 |
| 分享 | 筛选条件与当前照片会写进地址栏（`?y=2024&l=西湖#p=<id>`） |
| 导出 | 一键导出当前筛选结果为 JSON |

> 页面任意位置拖入文件夹都会弹出「松手即可导入」的遮罩，不用先切到导入页。

## 7.4 首页：照片点云

打开站点默认停在首页：**随机挑一张照片，把它的像素变成上万个三维点**，
鼠标移上去会有视差，按住可以旋转，滚轮缩放，旁边实时列出这张照片的拍摄参数。

**怎么做的**（`public/assets/pointcloud.js`）：

1. 把照片缩到 ~440px 宽读像素；
2. **细节优先采样**：与相邻像素差异大的地方（结构、暗部）多取点，避免变成一团均匀噪点；
3. **深度 = 亮度**：亮的地方朝观察者凸出来、暗的地方往后沉，再叠一点随机噪声，形成真正的立体感；
4. 透视投影 + 深度排序（远的先画），近处的点更大更亮，远处更小更暗；
5. **自适应亮度曲线**：先看整张图的平均亮度，夜空这类很暗的照片会自动提亮 gamma，
   否则点云黑成一片。实测夜景（ISO 1600 / 10s）也能看出云层与星点结构。

**交互**：

| 操作 | 效果 |
| --- | --- |
| 移动鼠标 | 轻微视差旋转（不点也能看出立体） |
| 按住拖动 | 自由旋转（上下限位，不会转丢） |
| 滚轮 | 缩放 |
| 点击画面 / 「换一张」 | 换一张随机的照片 |
| 「进入相册」 | 跳到相册 |
| 「看原图」 | 打开灯箱看这张的完整信息 |

点云只在首页可见时才渲染（切到别的页会暂停，不空烧 CPU）；系统开了"减少动态效果"时不再自转。

**设计风格**参考 DeepSeek Harness：中性偏蓝的深色阶（`#151517` 底、`#0f1115` 主文字）、
单一品牌蓝 `#4176e6` 作点缀、参数用等宽字体、细边框卡片、克制的圆角与留白。
这些颜色令牌定义在 `public/assets/style.css` 顶部的 `--dsw-*` 变量里。

## 7.5 重复照片检测怎么用

「重复」标签页会自动分组，并给出**建议保留**的那一张（像素最多 → 星级最高 → 文件最大）。

**它是怎么判断的**（`src/dup.js`）：

1. **结构指纹（dHash）**：把图缩到 9×8 灰度、逐行比较相邻像素明暗，得到 64 位指纹。
   缩放、重压缩、亮度微调都不改变它。
2. **颜色特征（色度）**：去掉亮度后统计 2×2×2 的色度分布。
   专门用来挡掉"结构撞车"的误报——实测中"杭州西湖"和"青岛海边"两张渐变图结构距离只有 3，
   但色度差异把它们分开了。**故意用去亮度的色度**，这样"同一张照片调亮 6%~12%"依然算重复。

**置信度分级**（页面上有标签）：

| 标签 | 含义 | 典型情况 |
| --- | --- | --- |
| 内容完全相同 | 结构距离 0 | 同一文件导了两遍、直接复制副本 |
| 高度相似 | 结构距离 ≤ 3 | 重复导出、改过尺寸、调过亮度、连拍 |
| 可能重复 · 请自己确认 | 结构距离 4~5 | 相似构图的不同照片，建议自己看一眼 |

两个滑块可以现场调整严格程度（结构 ≤ 5、颜色 ≤ 7 是默认值，改完会记住）：

* 误报多 → 把**结构**调到 3；
* 漏检多（比如同一张照片裁切过）→ 把**结构**调到 8~12，此时误报会明显增多。

**怎么处理**：每组里点「保留这张」，其余会被记入"忽略"（存在浏览器里，刷新仍在），
「清除忽略记录」可以撤销。注意：**这个页面只做标记，不会删除任何文件** ——
你确认之后自己去相册目录删冗余文件即可。真正省空间的是 `--copy` 时不要把原图放进仓库。

命令行也能看到统计：`npm run import -- --src "目录" --duplicates`，
分组明细会同时写到 `public/data/duplicates.json`。

## 8. 项目结构

```
photo-journal/
├─ src/                      共享模块（Node 与浏览器通用）
│  ├─ parse.js               文件夹名 / 文件名 → 日期 + 地点 + 标签
│  ├─ locationHints.js       地名表（可自由增删，含近似坐标）
│  ├─ exif.js                EXIF/XMP/IPTC/GPS 的归一化与格式化（不依赖 exifr，浏览器可直接用）
│  ├─ exif-parse.js          真正调用 exifr 解析文件（Node 用；浏览器由 build-vendor 打包）
```

## 9. 常见问题

**Q：点了「写入站点目录…」，站点里却什么都没出现？**
看页面顶部有没有**橙色横幅**。现在只要写入失败，横幅会常驻显示——切到任何页面、甚至刷新之后都还在，并写清原因。
最常见的原因是**目录选错了**：

* 必须选 **`photo-journal\public`**（里面有 `index.html` 的那个）。选成照片文件夹会提示"目录里没有 index.html，看起来不是站点根目录"。
* 选到 `photo-journal` 项目根目录也可以，导入器会自动用里面的 `public`。
* 写入成功时是**绿色横幅**，并自动切回相册、给新照片打绿色"刚刚导入"角标。

**Q：怎么确认到底写进了哪个目录？**
导入过程中会逐条记录（形如 `写入中 12/40：media/thumbs/xxxx.webp`），写在导入页下方，也保存在浏览器里。
导入页右下角有**「诊断」**按钮，点一下会输出环境、模块、数据链路的完整报告——把那段发我即可定位。
**兜底办法**：改点「下载 zip」，解压后把 `data/` 与 `media/` 覆盖进 `photo-journal\public\`，效果完全一样。

**Q：导入后统计/时间轴的数字没变？**
先看有没有绿色"刚刚导入"角标和绿色横幅。若写入成功但界面没更新，按 `Ctrl+R` 刷新一次
（正常情况下页面会自动重新读取索引，不需要手动刷新）。

**Q：首页点云是黑的 / 看不清？**
如果那张照片本身是大面积纯黑（比如长曝光夜空），点云自然偏暗——点云的颜色就是原照片的像素颜色。
程序已经按平均亮度自动提亮过一档；想更亮可以把 `public/assets/pointcloud.js` 里 `buildPoints()`
的 `gamma` 再调小一点（越小越亮）。换一张明亮些的照片对比一下就很明显。

**Q：点云卡顿？**
点的数量按画布面积自动定（9000~34000）。窗口越小点越少；也可以在 `home.js` 里给
`cloud.load(url, { maxPoints: 15000 })` 传个上限。

**Q：刚克隆下来打开站点，看到"站点里还没有照片"？**
这是正常的：`public/data` 与 `public/media` 是导入生成的，仓库里默认不带任何照片。
切到顶部「导入」标签，把文件夹拖进去即可；也可以先用 `npm run demo` 造一批示例照片试试。

**Q：拖进网页后按钮点了没反应 / 提示"没有发现可导入的文件"？**
确认拖的是**文件夹**而不是文件夹里的图片（两种都支持，但文件夹会递归扫描子目录）。
如果拖的是 `.zip`、`.lrdata`、`.xmp` 这类文件，会被自动跳过。
确认拖的是**文件夹**而不是文件夹里的图片（两种都支持，但文件夹会递归扫描子目录）。
如果拖的是 `.zip`、`.lrdata`、`.xmp` 这类文件，会被自动跳过。

**Q：网页里点「写入站点目录」报权限错误？**
浏览器要求每次写入都重新确认一次目录权限，弹窗里选"允许"即可。
也可以直接点「下载 zip」，解压后覆盖仓库里的 `public/` 目录——效果一样。

**Q：缩略图没生成 / 日志里报 `sharp 未安装`？**
命令行导入时 `npm install` 可能因网络没装上 sharp，重试 `npm install sharp` 即可；
确实装不上也能用（站点直接加载原图），只是慢。网页导入用的是浏览器自己的 Canvas，与此无关。

**Q：网页里的「导入」页不出现？**
它需要 `public/vendor/exif-parse.js`（把 exifr 打包给浏览器用）。
如果 `npm run build` 时提示无法生成，说明 esbuild 没装好：执行 `npm install` 然后 `npm run vendor`。
其余功能（浏览已导入的照片、命令行导入）不受影响。

**Q：我在照片文件夹里加了几张新照片，要重新导入吗？**
要。两种方式都可以重复运行：命令行会按内容哈希复用已有缩略图，只处理新增/变更的文件；
网页导入会跳过已经存在的缩略图（用同一份内容哈希）。

**Q：照片被重命名或移动了会怎样？**
记录 id 由"相对路径 + 文件大小"哈希得出，移动后会被当成新照片（旧记录会消失，重新生成）。

**Q：支持 HEIC / RAW 吗？**
命令行（sharp）与网页（浏览器解码器）能力不同：
命令行的索引总能读，缩略图取决于 libvips；网页里 `.heic/.tif/.dng/.cr2/.nef...`
会**读取拍摄参数但不生成缩略图**（浏览器解不了），这时建议先在 Lightroom 里导出 JPEG 再入库。

**Q：支持多人/多设备浏览吗？**
支持。部署后就是普通网页；数据库、账号体系一概没有（这也是它简单、不泄露数据的原因）。
注意：写回目录只发生在本机浏览器里，不会上传任何照片。

**Q：照片里有隐私（家庭住址、GPS）怎么办？**
三种做法：① 网页导入时对单张点「修正」改掉地点，或命令行用 `overrides`；
② 设置 `previews: false` + 不放原图，站上只有缩略图；③ 导入后在 `public/data/search.json` 里手工删掉 `g` 字段
（或在 `src/exif.js` 的 `pickGPS` 里直接返回 `null`，一次性全部不显示坐标）。

**Q：地图能不能换成高德/Google 那种真实底图？**
可以，但要自己申请 Key：把 `public/assets/map.js` 里的 canvas 绘制换成瓦片图层即可。
默认方案故意选择"离线海岸线"，因为它零成本、零授权风险、不向外泄露你的拍摄位置。
