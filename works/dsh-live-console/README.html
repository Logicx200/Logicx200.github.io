dsh-live-console

一个 host 为主的 DSH 插件：用一个固定的 HTML 页面替代桌面小组件，实时显示 每个对话里运行的命令、输出日志、进度条，以及 token 花费 / 缓存命中 / 账户余额。页面由 DSH 自带的 HTTP 服务直接提供，不额外开端口；另带一个很小的 client 半边，只在对话顶栏 加一个“控制台”按钮。

旧桌宠/看板（F:\dsh-usage-widget）没有被停用，等新页面确认后再说（见文末）。

当前状态（2026-11-05）

  • 已通过 junction 挂进 profiles/desktop/node_modules，并加入 dsh.profile.bundles（package.json.bak-live-console-* 是安装前备份）。
  • 第一版（页面/进度/日志/自动打开）已在运行中的 0.2.1-rc.5 上热组合并实测。
  • 第二版（用量/花费/余额 + 顶栏“控制台”按钮）已写完并通过离线自检， 但它是 host 源码 + 新增 client half，需要重启一次 DSH 才会加载。
  • 页面地址写在 $DSH_HOME\live-console\url.txt；访问 key 在 $DSH_HOME\live-console\key.txt（已预置为当前 key，重启后 URL 不变）。
  • 真机验证（第一版）：页面已自动在浏览器打开（服务端 SSE clients=1）；运行中的长任务 从 [progress 5/20] 解析为 25% → 55%，ETA 从 21s 收敛到 6s；事件流里能看到 tool/call、tool/result、step/start 等。
  • 第二版离线验证：用量扫描实测 2.9 s / 44 个日志 / 61 MB，得到 $25.86、9,628 次调用、缓存命中 99.6%；余额接口返回 ￥36.04； 页面真机渲染（无头 Edge + demo）确认花费条与按模型明细正常。

如果浏览器把页面关了，重新打开 url.txt 里的链接即可；下次某个对话开始跑命令时， 插件发现没有页面连着，也会自动再打开一次。重启之后，DSH 顶栏也会出现“控制台”按钮。

它做什么

  • 一个页面：http://127.0.0.1:<GUI端口>/live-console?k=<随机key> （<GUI端口> 是 DSH 当前 Web 端口，本机通常是 4620）。
  • 自动打开一次：插件激活后约 2.5 秒打开默认浏览器；之后如果页面被关掉， 下一次对话开始跑命令时会再打开一次（同一时刻只保留一个页面，不刷屏）。 页面内自动跟随最近活跃的对话，也可以手动点左侧会话固定查看。
  • 显示什么：
    • 顶部花费条：今日花费（$ / ￥）、总计、账户余额、缓存命中率、调用次数、当前峰/谷时； “用量详情”展开后是按模型的调用/tokens/花费明细。
    • 左侧：所有对话（标题、目录、运行状态、当前轮/步、运行中任务数），子会话默认隐藏。
    • 中间：命令卡片（命令原文、状态、进度条、已运行时间、输出字节/行数、最后一行输出、 可展开实时日志）。
    • 下方：对话事件流（标题、轮/步、工具调用、工具结果、用户/模型消息摘要）。
  • 数据来源：
    • 任务/日志：ctx.jobs 的事件与输出环 + session/event 持久事件流 + api-session/*。
    • 花费：扫描 $DSH_HOME\sessions 里的 v3/v4 会话日志，按每次调用自己的时间戳套 DeepSeek 峰谷价目表（USD），再按配置汇率折算 CNY；只在激活时和“页面打开期间每 2 分钟” 扫一次，不跟随每次请求。
    • 余额：DEEPSEEK_API_KEY（来自 $DSH_HOME\.credentials.yaml 的 refs:）请求 https://api.deepseek.com/user/balance，成功缓存 60 秒。
  • DSH 顶栏按钮：client 半边在对话顶栏注册“控制台”按钮；点击后向 host 的 /api/live-console/url（走 DSH cookie 认证）取带 key 的地址，再 window.open 交给 Electron 用默认浏览器打开。

进度条：三级模型（不假装精确）

级别来源页面标签
1. 输出进度程序自己打印的 42% / [progress 3/10] / step 3/10；jobs 注册表自己的 progress 行输出进度 / 注册表进度
1b. 进度文件命令把输出重定向到文件时（> run.log、-o out.txt、--output、-OutFile、`tee`），从文件尾部解析进度文件
2. 历史估算同一命令此前运行的中位耗时 / 中位输出量；最多估算到 95%，真正的 100% 只由任务结束给出历史耗时估算 / 历史输出量估算
3. 活动条完全没有数字信号：动画条 + 已运行时间 + 输出字节/行数 + 最后输出时间无进度信号

为什么没有"真进度"：程序不报告进度时，任何百分比都只能是估算。这里的选择是： 能拿到的真实进度优先；拿不到就用同一个命令的历史估算（会明确标"估算"）；再拿不到 就诚实地显示活动条，而不是编一个数字。

自动进度约定：插件通过 ctx.systemPrompt.section() 给所有对话注入一段系统提示， 要求长时间命令主动打印进度行，并在重定向输出文件时把进度写进文件。这样不需要每个对话 都手动提醒模型——以前"要求当前对话输出进度它就能做到"，现在是默认行为。 已有输出 x% / n/m 的程序无需任何改动。

安装（desktop profile）

包目录：F:\DeepSeek工作区\dsh-live-console-v15。

# 1) 链接进 desktop profile 的 node_modules
New-Item -ItemType Junction `
  -Path  "$env:USERPROFILE\.dsh\profiles\desktop\node_modules\dsh-live-console" `
  -Target "F:\DeepSeek工作区\dsh-live-console-v15"

# 2) 在 profile 的 dsh.profile.bundles 里加上 "dsh-live-console"
#    $DSH_HOME\profiles\desktop\package.json

host 源码改动不会热重载：改了 src/ 之后需要重启宿主进程（或重启桌面应用）才生效。 新增 bundle 层本身是否热组合取决于版本；已验证 0.2.1-rc.5 下追加条目后会重新组合。

页面地址会写到：

$DSH_HOME\live-console\url.txt        # 一行，含随机 k
$DSH_HOME\live-console\history.json   # 每个命令的历史耗时/输出量（用于估算）

安全

  • 路由只接受本机回环地址（allowNonLoopback: false，默认）；页面与数据接口都要求 URL 里的随机 k（首次生成后持久化在 key.txt，重启不变）。这样即使以后开启远程访问， 链接也不容易被猜。
  • 页面带 CSP（default-src 'none'，只允许内联样式/脚本与同源连接）、X-Frame-Options: DENY。
  • 命令输出在页面里全部经 HTML 转义 / textContent 渲染，不执行输出内容。
  • 注意：控制台页面不使用 DSH 的 cookie 认证（那是给 /api 与 SPA 的），所以链接本身 就是凭证；不要把它转发给别人。

已知限制

  • 花费来自会话日志扫描：价格表写死（2026-09-10 生效的 Flash/Pro 峰谷价）， 峰谷按 UTC 周一至周五 01–04、06–10 判定；如果 DeepSeek 之后调价，金额会偏。
  • 余额依赖 DEEPSEEK_API_KEY 与网络；取不到时显示 — 并把原因放在 tooltip。
  • 用量扫描在激活时约 2–3 秒 CPU，页面开着时每 2 分钟一次；不需要可在配置里关掉 usage / balance。
  • 第二版新增了 host 源码与 client 半边：需要重启一次 DSH 才会加载；重启后 顶栏“控制台”按钮和页面花费条才会出现。
  • 插件激活前已经在跑的任务不会补登记（激活后的新命令都会出现）。
  • 老会话的标题：插件激活时会对当时还活着的会话回填标题（从它的 session 事件里找最新的 session/title）；已归档会话不在实时会话表里，不会显示。
  • 估算依赖同一命令的完整命令行文本；命令里带随机参数（时间戳、临时文件名）时命中率会下降。
  • 旧桌宠的移除方式见 F:\dsh-usage-widget 审计结论：先禁 DshUsageWidgetWatchdog 再停 DshUsageWidget，install-startup.ps1 -Uninstall 有 bug 不会删 watchdog。

对话事件摘要增强（2026-11-05）

对话事件不再只显示事件类型，而是这一步实际做了什么：

  • 工具调用：运行命令 · python sim.py、读取文件 · docs/a.md、搜索 · TODO、搜索网页 · … 等；
  • 工具结果：工具名 + 成功/失败 + 结果摘要 + 耗时（如 pwsh 完成 · … · 622ms）；
  • 命令任务：启动命令 · … / 命令结束 · completed · exit code: 0；
  • 助手步骤：模型回复 · 346 tokens：这一步的文字摘要；
  • 轮/步：第 8 轮 · 第 13 步开始 / 结束、第 8 轮结束（completed）。

顶栏入口的安全替代（2026-11-05）

  • 不再启用 client bundle dsh-live-console-ui，改为 host 侧通过 webServer.tapIndex 往应用首页注入一个右下角浮动“控制台”按钮；
  • 按钮点击时向已认证的 /api/live-console/url 取带 key 的页面地址，再 window.open 交给 Electron 打开默认浏览器；
  • 首页改动只需刷新一次应用页面（或下次启动）即可出现，不参与启动时的 client 模块扫描，因此不会重现 boot 失败。

浮动“控制台”按钮（2026-11-05 修正）

  • webServer.tapIndex 只作用于 HTTP 首页；桌面应用窗口的 index 由 Electron 本地提供，注入行来自 host 启动时通过 IPC 发送的 collectIndexInjections()。
  • 因此改为订阅 webserver/index-inject 并推入 { kind: script, placement: head, text: ... }，这才是桌面窗口消费的通道。
  • 该注入在应用启动时读取一次，所以按钮需要重启一次 DSH 才会出现在窗口右下角；页面本身无需重启。

重启后标题/对话为空修复（2026-11-05）

  • 原因：恢复的会话在插件激活之后才发布，原来只回填一次，因此标题为空、最近对话为空（只剩启动后的新消息）。
  • 修复：每 2 秒轻量扫一次 ctx.sessions.list()，对尚未回填的 session 各扫描一次自己的事件日志，恢复标题和最近 6 条对话；已扫描的会话直接跳过。
  • 该修复热加载后立即生效，无需重启。

对话图谱页面（2026-11-05）

  • 入口：控制台顶栏“图谱”按钮，或直接访问 /live-console/graph?k=<key>；
  • 每个持久化用户对话 = 一个节点，节点保存标题、目录、时间、消息数、关键词和最多 8000 字内容摘要；
  • 两个对话共享至少一个关键词就连线，边携带共享关键词列表，线宽随共享关键词数量增加；
  • 关键词提取：清洗掉 harness 注入的运行时上下文伪用户消息后，用 CJK bigram/trigram + 英文词的 TF-IDF 排名，每个节点取前 10 个，并去掉“传感/感器”这类被更长词包含的重复项；
  • 内部 subagent/teammate 会话不进入图谱（它们不是用户对话）；
  • 数据由扫描 $DSH_HOME/sessions/**/session.v*.jsonl.zstd 生成，单飞 + 60 秒缓存；“刷新数据”强制重扫；
  • 页面支持搜索、关键词高亮、点击节点查看内容、拖拽/缩放/重新布局。

无损上下文归档（2026-11-05）

  • 控制台/图谱页“归档”按钮，或访问 /live-console/context-archive?k=<key>，下载 dsh-context-archive-*.tar.gz；
  • 归档内容：manifest.json（每会话 SHA-256、大小、header）+ README.txt + 原始 sessions/<workspace>/<session>/session.vN.jsonl.zstd；
  • 原文件按字节复制，不解码、不截断、不重排；DSH 日志本身是 zstd 无损压缩，外层 gzip 只做打包；
  • 当前规模：45 个会话，约 63 MB（原始压缩日志已占 60 MB，主要是容器开销）；
  • 这是存储/传输出口；无损压缩不会减少模型上下文的 token，模型输入仍需解压后的文本。

图谱关键词/节点样式（2026-11-05）
